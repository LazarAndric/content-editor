# 0.4.0 validation — 2026-10-27

- All 24 package tests pass, including the real SunEditor distribution in jsdom.
  Browser-only canvas/layout APIs are stubbed for those tests; visual behavior
  was also checked separately in a real browser.
- Fixed synthetic JSON/XLSX fixtures generated by 0.3.0 import into 0.4.0.
  The original 0.3.0 reader also accepted a newly exported 0.4.0 workbook.
  All public 0.3.0 export paths are retained.
- An existing consumer's 138 tests passed against an isolated copy of the new
  package. Two tests required updating their expected vendor asset URLs for the
  editor replacement. Without that test-only adjustment, 136 passed and those
  two failed on their old editor asset expectations. Consumer files, installed
  packages, lockfiles and saved content were not changed by that check.
- A clean temporary installation from the packed npm archive passed imports of
  every non-React public entry point, CLI initialization, dev startup, editor
  JavaScript/CSS/license requests, browser modules and XLSX export. React was
  exercised through the consumer regression tests.
- Browser checks covered loading legacy HTML and a table without rewriting the
  saved file, editing, switching tabs, saving, reloading and formatting controls.
  Unedited strings remain byte-for-byte unchanged during unrelated saves.
- Static export includes package and bundled browser dependency license notices.
  The npm archive excludes tests, application content, logs, credentials and
  node_modules. It is approximately 70 KB compressed, before installing dependencies.

The dependency audit reports two moderate entries through ExcelJS's uuid
dependency. The advisory concerns buffer handling in uuid v3/v5/v6; the installed
ExcelJS source uses uuid v4 without a supplied buffer. No forced ExcelJS downgrade
or unsupported major dependency override was applied. Recheck the audit before
the registry release.
